# Complete Game Production Backlog

## 목적과 사용 규칙

이 문서는 IncrementalDiablo가 기술 데모나 HUD 검증 묶음에 머무르지 않고, 판매 가능한 PC 게임까지 이어지기 위한 **완성형 생산 백로그**다. `13_ReleaseReadinessAndProductionGates.md`가 제품 게이트를 정의하고, 이 문서가 게이트를 통과시키는 큰 작업 순서를 정의하며, `10_PlayableLoopMvpAutomationPlan.md`가 오늘 실제로 수행할 첫 작업을 한 줄로 가리킨다.

일일 자동화는 다음 규칙을 따른다.

1. `10`의 `Next / Product work / P0`는 이 문서에서 아직 끝나지 않은 가장 앞선 P0 항목이어야 한다.
2. 활성 P0가 남아 있으면 HUD 문구, 설정 버튼, 정적 점검, 문서만의 작업을 선택하지 않는다. 그런 작업은 활성 P0를 직접 막거나 회귀를 고칠 때만 허용된다.
3. 모델·애니메이션·맵 배치처럼 Unity Editor의 시각 판단이 필요한 작업은 코드·데이터·프리팹 계약을 먼저 진행하고, 남은 수동 단계는 정확한 오브젝트/에셋/검증 기준으로 넘긴다. 에셋 부재는 실제 차단 요인으로 보고하며 HUD 작업으로 우회하지 않는다.
4. 한 항목은 플레이어가 실제로 보고, 조작하고, 위험을 감수하고, 보상 또는 장기 목표를 얻는 변화가 있어야 완료된다. 하네스 통과만으로 완료되지 않는다.

## 현재 선택

**현재 P0:** `E3-B | 플레이어와 적의 모델·애니메이션을 실제 전투 상태에 연결`

이 작업은 기존의 플레이어/적 프리팹과 전투 권한을 대체하지 않는다. 먼저 프로젝트 안의 사용 가능한 라이선스 에셋, 모델, 리그, 클립을 조사하고, 실제 Hero와 첫 근접 적에 `Idle`, `Move`, `Attack`, `Hit`, `Death`가 전투 상태와 함께 보이도록 연결한다. 사용 가능한 아트 에셋이 없다면 필요한 원본 에셋 형식·라이선스·임포트 경로를 한 번만 명확히 요청하고, 그 동안에도 애니메이터 파라미터·프리팹 바인딩·상태 이벤트처럼 코드로 결정 가능한 부분을 완료한다.

`E3-A` HUD 설정/첫 세션 QA는 2026-07-10 사용자 확인으로 완료된 회귀 전용 항목이다. 더 이상 일일 작업 선택을 막지 않는다.

## 게이트 연결

- R0~R2의 기존 루프·반복성·알파 기반은 유지한다.
- R3은 E3-B~E3-E가 끝난 **보여줄 수 있는 전투 버티컬 슬라이스**다. HUD QA만으로 통과하지 않는다.
- R4 Early Access Candidate는 Phase F와 G의 콘텐츠/경제/장기 진행이 실제로 작동하고 H의 필수 검증이 시작될 수 있는 상태다.
- 900시간 목표는 R4 이후의 확장 원칙이다. 숫자를 채우기 위한 수작업 콘텐츠 나열이 아니라 모듈, 행동 템플릿, 드롭 규칙, 소모처, 저장 호환을 늘려 달성한다.

## 일일 보고 금지 항목

- 새 텍스트 한 줄, HUD 토글, 문서 문장, 하네스 통과만으로 ‘게임 진행’이라고 보고하지 않는다.
- 이미 완료된 E1/E2/E3-A 작업을 기능 추가의 명분으로 다시 열지 않는다.
- 모델, 애니메이션, 맵, 사운드, 전투 피드백이 필요한 활성 P0가 있을 때 별도 HUD/문서 마이크로 작업으로 시간을 쓰지 않는다.
