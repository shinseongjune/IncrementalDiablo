# Production Roadmap

## 작업 선택 규칙

매일 가장 앞선 `P0`만 진행한다. 문서, HUD 문구, 하네스, 회귀 체크는 그 P0를 직접 막거나 깨진 경우에만 다룬다. 완료된 작업을 다시 열어 작은 개선을 만들지 않는다.

## 현재 P0 — E3-D 첫 물리 던전 (진행 중)

E3-C는 텔레그래프와 반응성 조정을 배포한 뒤, 최종 회피 감각 확인을 이후 행동 패키지로 보류했다. 다시 열지 않는다.

완료: `DungeonTraversalController`와 `DungeonTraversalTrigger`가 자동 한 방 시작을 물리 방 진입으로 바꾸고, 방 클리어 뒤 다음 길을 열며, 방별 스폰 지점을 선택하고 마지막 보상 뒤 입구 귀환을 처리하는 계약을 소유한다. 기존 `CombatRoom` 전투 판정과 `ExpeditionDirector` 보상 권한은 그대로다.

다음 E3-D 체크리스트:

- [x] 순서 있는 방 진입·길 개방·퇴장/귀환 코드 계약을 만들었다.
- [ ] `Gameplay`에 입구와 두 개 이상의 연결 전투 방, 각 방의 `EnterRoom` Trigger, 마지막 `ReturnToEntrance` Trigger를 배치한다.
- [ ] NavMesh를 굽고 `입구 → 방 전투 → 길 개방 → 다음 방 → 보상/퇴장 → 입구 귀환` Play Mode 증거를 확인한다.

E3-B 완료: `HeroDefault`와 `OrcPADefault` 시각 Prefab을 기존 `Player`/`PF_DungeonEnemy_Melee` 루트의 `Model` 자식으로 연결했고, 공통 `Combat` 상태기와 Hero/Orc Override Controller를 적용했다. 사용자 Play Mode에서 두 전투 주체의 Idle, Move, Attack, Hit, Death를 확인했다. 이후 모델·Animator 연결은 회귀 전용이다.

## 첫 버티컬 슬라이스

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| E3-B | 완료 — 모델·애니메이션 연결 | 실제 전투 주체의 다섯 상태가 보인다. |
| E3-C | 보류 — 행동 패키지와 재검토 | 텔레그래프와 반응성 조정은 배포했으며, 최종 회피 감각은 별도 행동 작업에서 확인한다. |
| E3-D | 현재 P0 — 첫 던전 맵 | 입구, 연결 방, 전투, 보상/퇴장·귀환이 물리적으로 이어진다. |
| E3-E | 완성 세션 | 전선 → 계약 → 전투 → 보상/제작 → 방어 투자 → 저장/불러오기가 한 세션에서 이어진다. |

## 게임 완성 단계

| 단계 | 목표 |
| --- | --- |
| F | 재사용 가능한 모델/애니메이션/VFX/SFX 프리팹, 모듈형 맵, 적/보스 행동, 아이템 빌드·제작 소모처, 방어 로드아웃을 만든다. |
| G | 다층 진행, 엔드게임 반복, 경제 안정성, 저장 호환, 성능을 실제 콘텐츠와 함께 만든다. |
| H | 접근성·입력·정식 설정, 빌드/QA/배포 준비를 끝낸다. |

## 완료 기준

- 버티컬 슬라이스: 실제 모델/전투/맵/보상이 연결된 플레이 가능한 세션.
- Early Access: 여러 콘텐츠 템플릿, 장기 소모처, 막히지 않는 진행, 저장/성능/빌드 품질.
- 이후 확장: 900시간 목표는 콘텐츠 수작업이 아니라 템플릿, 드롭 규칙, 소모처, 로드아웃의 조합으로 만든다.
