# Dungeon Expedition System

## 목적

원정은 손으로 만든 방 템플릿을 시드 기반으로 조합해, 직접 조작 전투의 위험과 보상 확정 선택을 반복하게 만든다. 고정 맵을 한 번 통과시키거나 같은 방만 되풀이하는 구조가 아니다.

## 최종 원정 계약

- 원정 시작 시 `runSeed`, 계약, 시작 깊이를 정한다. 각 깊이는 이 값으로 방 템플릿, 적·오브젝트·장애물 배치, 조우, 보상 계획을 결정한다.
- 현재 방은 단 하나의 런타임 인스턴스다. 심층 출구를 선택하면 현재 방을 해제하고 다음 방 템플릿을 불러온다. 이전 방의 오브젝트와 적은 다음 방에 남지 않는다.
- 방을 정리하면 `ReturnPortal`과 `DeeperExit`가 열린다. 귀환 포탈은 미확정 원정 보상을 확정하고 거점으로 돌아가며, 심층 출구는 깊이를 1 올리고 더 큰 위험·보상 계획의 다음 방을 연다.
- 사망은 원정을 종료하고 미확정 보상만 폐기한다. 이미 귀환으로 확정한 장비·재료·전선 진행은 잃지 않는다.

## 소유권

- `ExpeditionDirector`는 계약, 원정 시드, 깊이, 현재 방 계획, 미확정 보상, 성공·실패 상태를 소유한다.
- `DungeonRoomLoader`는 카탈로그가 시드로 한 번 고른 현재 방 템플릿의 로드·해제, 입구 배치, 귀환 시 영구 `Gameplay`의 거점 복귀 위치 배치를 소유한다. 저장된 템플릿 ID가 카탈로그에 없으면 다른 방을 임의로 고르지 않고 복원을 막는다. 같은 템플릿 ID가 연속으로 선택돼도 방 시드가 바뀌면 이전 Scene을 해제하고 다시 로드한다.
- `DungeonRoomTemplate`은 additive Scene의 루트 계약이다. 입구, 귀환 포탈, 심층 출구, 적·오브젝트·장애물 앵커, 방 전용 NavMesh와 각각의 `ReturnPortal`·`DeeperExit` Trigger를 제공한다. `DungeonRoomLoader`는 현재 방 Scene 하나만 유지하고, 방 정리 상태에서만 두 Trigger를 연다.
- `CombatRoom`은 `DungeonRoomLoader`가 현재 `DungeonRunPlan`과 같은 템플릿을 로드하기 전에는 시작하지 않는다. `EnemySpawner`는 로더가 연결된 동안 그 템플릿의 적 앵커에서만 생성·추적하고, 생성 적은 해당 additive Scene의 루트에 둔다. `ExpeditionDirector`는 보상 확정 권한을 유지한다.
- 기존 `DungeonTraversalController`와 `DungeonTraversalTrigger`의 같은 씬 방 순서 계약은 전환용 기반이다. 최종 원정의 맵·출구·보상 흐름을 소유하지 않는다.

## 배치 규칙

- 모든 무작위 배치는 시드와 앵커 목록에서 재현 가능해야 한다. 런타임 전역 난수만으로 방 내용을 정하지 않는다.
- 적·오브젝트·장애물은 입구, 귀환 포탈, 심층 출구의 NavMesh 경로를 막을 수 없다. 유효 앵커가 부족하면 해당 배치 조합을 버리고 다시 계획한다.
- 방의 지형과 NavMesh를 런타임에 무작위 생성하지 않는다. 플레이 가능한 품질은 손제작 템플릿과 사전 검증된 앵커가 보장한다.

## 첫 플레이 가능 기준

1. 서로 다른 방 템플릿 둘 이상에서 시드 기반 배치가 달라진다.
2. 첫 방을 정리한 뒤 귀환 포탈을 타면 미확정 보상이 한 번만 확정된다.
3. 심층 출구를 타면 이전 방이 해제되고 다음 깊이의 방·적·보상 계획이 로드된다.
4. 진행 중 저장/불러오기는 같은 시드, 깊이, 방 계획, 미확정 보상을 복원한다.
5. 사망은 미확정 보상만 폐기하고 다음 원정 선택으로 돌아간다.

## 검증

- 원정 데이터·저장 계약 변경: 빌드와 새/기존 저장 마이그레이션 확인.
- 방 템플릿·앵커·NavMesh 변경: 방별 Play Mode 경로와 포탈 선택 확인.
- 보상 수치 변경: 해당 분모와 밸런스 내보내기 확인.
