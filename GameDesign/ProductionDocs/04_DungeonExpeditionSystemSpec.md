# Dungeon Expedition System

## 목적

던전은 직접 조작으로 위험을 읽고 대응해 장비와 재료를 얻는 루프다. 전선 자원을 단순히 다른 화면에서 소비하는 곳이 아니다.

## 현재 계약

- `ExpeditionDirector`가 깊이, 계약, 조우, 진행, 보상 대기 상태를 소유한다.
- `CombatRoom`과 `EnemySpawner`가 실제 전투와 스폰을 연결한다.
- `DungeonTraversalController`와 `DungeonTraversalTrigger`가 입구, 현재 방 진입, 방 클리어 뒤 길 개방, 퇴장·귀환과 방별 스폰 위치 계약을 소유한다. `EnemySpawner`는 그 위치에서만 적 생성·추적을 맡고, 전투 판정과 보상 권한은 옮기지 않는다.
- 계약은 진입 전 위험/보상 차이를 보여 주며, 활성 실행 상태와 보상은 저장/불러오기와 일관돼야 한다.
- 실패는 명확한 복귀와 다음 선택을 남기고, 성공은 보상 처리로 연결된다.

## E3 버티컬 슬라이스 요구

1. Hero와 첫 적이 실제 모델/애니메이션 상태로 이동, 공격, 피격, 사망을 보여 준다.
2. 엘리트 또는 보스 하나는 선행 동작, 피할 수 있는 공격, 실제 명중/피해, 보상 처리로 플레이어 대응을 요구한다.
3. 첫 던전은 입구, 순서 있는 방 진입 트리거, 방 클리어 뒤 열린 경로, 보상/퇴장·입구 귀환으로 이어지는 의도된 맵이다.
4. 새 저장에서 계약 선택부터 보상까지 개발자 설명 없이 진행된다.

## 확장 규칙

- 적 행동, 스폰, 보상 깊이는 데이터 또는 재사용 상태 규칙으로 조합한다.
- 새 방/테마는 모듈과 프리팹으로 추가한다. 손제작 맵 하나의 수치만 바꿔 반복시키지 않는다.
- 전투 상태와 보상 권한을 화면 표현이나 Animator가 소유하지 않는다.

## 검증

- 코드/프리팹 계약: 빌드와 최소 하네스.
- 전투 타이밍, 텔레그래프, 카메라, 맵 동선: 짧은 Play Mode 확인.
- 계약/조우 수치 변경: 해당 내보내기 스크립트만 실행한다.
